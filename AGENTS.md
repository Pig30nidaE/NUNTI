# NUNTI visual work conventions (merge into existing AGENTS.md)

- Scope: NUNTI is a Pleos Connect Android Automotive app, not a mobile-first website. Preserve the existing application's architecture and API contracts; inspect code before changes.
- Product identity: A small, rounded, friendly travel companion whose appearance transforms with the route, destination and explicitly chosen mood; strongly recognizable silhouette, consistent face geometry, warm but restrained emotion. Do not emulate an existing copyrighted mascot.
- Canonical source of truth: `docs/NUNTI_DESIGN_CONTRACT.md` and the approved master character reference in the project (if present). Prompt-based variants must retain canonical face/body identity.
- Skin V2: Apply `docs/redesign/SKIN_SYSTEM_V2.md` first for full-skin appearance and transformation. This scope supersedes accent-only or fixed outfit/head contour rules in the legacy contract and Nunti skills. Begin with visible base Nunti and transform in place using local layers. Keep `MOCK_SKIN_MODE` enabled through verification and explicit user approval.
- Variant mapping: Stable output for the same input + versioned seed. Distinguish explicit user mood from vehicle-inferred events. Handle unavailable route/destination/scenery fields with documented fallbacks.
- Driving safety: Transformation sequences are parked/pre-departure or post-arrival only. During driving restrictions, do not play decorative animations, videos, auto-scroll, or attention-grabbing motion. Use `CarUxRestrictions` and the official Pleos UX/driver-distraction guides. Don't change driving restrictions simply to show an animation.
- Design implementation: Import official Pleos display and design assets; use Figma native components, variables, and auto layout; adapt to the actual emulator dimensions, layout and multiwindow mode. Do not alter platform navigation or reserved driving-data areas.
- Assets: Prefer approved local PNG/WebP/SVG, Figma export, Lottie/dotLottie or deterministic Compose animation over image/video generation on every drive. Each accepted asset has an owner, source prompt, version, export settings, licensing note and fallback.
- Verification: For all UI work, compare Figma screenshot vs emulator. Inspect driving/parked transition, loading and failure fallback, accessibility, contrast, visual scale, memory/CPU and smoothness before claiming completion.
- Quality bar: Present at least two alternative visual directions early. Move to production only after choosing one. Keep generated concepts separate from approved production assets. Preserve exact existing technical behavior unless explicitly requested.
