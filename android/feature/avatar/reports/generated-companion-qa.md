# 경로 리본 → 완성 RGBA 동반자 검증

2026-11-03. 외부 API, 이미지 생성 모델, 새 자산 및 리깅을 실행하지 않았다. 기존 `RouteBornCompanion`은 수정하지 않았다.

`GeneratedCompanion`은 호스트가 검증하고 디코딩한 원본 이미지와 실제 입력 경로를 받는다. A 리본 시안을 적용했다. 경로 전체가 처음부터 옅게 보이며, 동일한 순서의 384개 점과 연속 펜끝이 원본 이미지의 행별 알파 폭을 따라 일곱 번 감기는 리본으로 변한다. 리본은 원형·타원형 몸체 프리셋을 사용하지 않는다.

이미지 알파는 준비 후 `Dispatchers.Default`에서 한 번 읽는다. 최대 192×192 표본으로 max-pool한 뒤 빈 행은 인접한 실제 행의 폭 사이를 보간한다. 이미지·경로를 키로 계산 결과를 보관하며 프레임마다 원본 픽셀을 읽지 않는다. `birthProgress=1`로 처음 표시하는 복원 화면과 정적 썸네일은 알파 분석을 생략한다. 준비 중에는 입력 경로만 표시한다.

호스트는 `onFormationPrepared` 콜백 전 진행값을 0에 유지한다. 비동기 계산이 늦어도 중간 morph 지점으로 건너뛰지 않게 하는 준비 경계다. 콜백은 현재 이미지·경로의 기하가 존재하고 `ready=true`, 이미지가 null이 아니며 진행값이 1 미만일 때만 탄생 구간별 한 번 전달한다. 최신 콜백은 `rememberUpdatedState`로 읽는다. 정적 복원에서는 콜백도 호출하지 않으며, 동일 이미지로 다시 탄생을 시작하면 준비 효과가 다시 진입한다. 이전 이미지의 계산 효과는 취소되고 현재 이미지에 묶인 기하만 전달한다.

같은 리본의 붓이 지나간 부분부터 원본 PNG를 공개한다. 흰 붓 마스크와 마지막 잔여 마스크를 먼저 합친 뒤 `SrcIn`으로 원본을 **한 번만** 그린다. 따라서 원본의 부분 알파를 두 번 겹쳐 불투명하게 만들지 않는다. 마스크는 실제 이미지 사각형 밖으로 나가지 않도록 clip한다. 중앙 원형 reveal은 제거했다.

실제 Android의 약 .60 프레임에서 붓 폭이 회전 간격보다 좁아 얼굴·몸체가 가로 띠로 나뉘는 현상을 확인했다. 공개 마스크의 최소 붓 폭을 `알파 유효 높이 × image fit 높이 ÷ 7회전 × 1.2`로 보정했다. 최종 폭은 이 값과 시간에 따른 8→32 stage px 중 큰 값이다. 가로형·세로형 모두 실제 리본 간격보다 넓게 겹쳐 칠한다. 밝은 리본의 두께·앞뒤 overlay와 원본 PNG 자체는 바꾸지 않았다.

얼굴·색·비율과 이미지 파일은 그대로 유지한다. 리본의 앞쪽 절반만 원본 위에 다시 그려 앞뒤 깊이를 주고, 작은 따뜻한 펜끝과 진주색·민트색·금빛 하이라이트를 사용한다. 마지막에는 전체가 조금 눌렸다 돌아오는 탄성 착지와 접지 그림자가 있다. 완성 뒤의 작은 숨쉬기·기울기는 전체 이미지에만 적용한다. `animate=false`이면 착지와 idle 변형이 없다.

## 타임라인

호스트의 6.9초 타임라인에 맞춘 정규화 진행값이다. 모델이나 네트워크 진행률을 뜻하지 않는다.

| 구간 | 표시 |
|---|---|
| 0–.18 | 실제 경로 전체와 이동하는 펜끝 |
| .18–.50 | 같은 경로 표본을 이미지 알파 폭의 리본으로 연속 변형 |
| .50–.90 | 같은 붓에서 원본 이미지를 칠함; 붓 폭은 8→32와 실제 회전 간격의 1.2배 중 큰 값 |
| .88–.98 | 붓으로 남은 미세 영역의 마스크를 부드럽게 완성 |
| .90–1 | 전체 탄성 착지; .98에 리본·펜끝 제거 완료 |
| 1 | 마스크 없는 원본 전체; idle 또는 정적 표시 |

잔여 마스크는 .98에 이미 완성된다. 따라서 마지막 1 프레임에서 원본 전체가 갑자기 나타나는 전환은 없다. 이미지·리본·마스크에는 같은 변형을 적용해 착지 중 붓과 이미지의 위치가 어긋나지 않게 했다.

`ready=false` 또는 `image=null`이면 원본 픽셀, 알파로 만든 리본 형상, 이미지 그림자를 표시하지 않는다. 차량·화면 생명주기 조건이 불허하면 호스트가 이 composable을 호출하지 않는다. 렌더러에는 네트워크·음성·보관 동작이 없다.

## CPU 검증

기존 로컬 JDK와 Kotlin compiler를 사용했다. 다운로드와 Gradle 실행은 하지 않았다.

```sh
bash android/feature/avatar/scripts/test-generated-companion.sh
```

최종 실행은 PASS이다. 로그와 검증한 소스 SHA-256은 [generated-companion-tests.txt](generated-companion-tests.txt)에 있다.

- 준비 여부·이미지 존재 여부를 조합한 4,004개 프레임에서 준비 전 reveal·파생 형상 morph·잔여 마스크·이미지 그림자가 모두 0이다.
- 직선·굽은 경로·닫힌 경로 세 가지에 서로 다른 알파 행 폭 두 가지를 적용했다. 384개 표본의 입력 순서, 정확한 시작·끝점, 일곱 회전, 표본 사이 펜끝 연속성, 전체 타임라인의 펜끝 이동 상한을 검증했다.
- 알파 폭이 좁아지는 이미지에서는 해당 높이의 리본 폭도 실제로 좁아진다. 빈 행은 전체 사각형으로 확장하지 않는다.
- 가로·세로 이미지 fit 각각에 알파 형상 두 가지를 적용했다. 초기·중간·후반 paint 폭이 실제 세로 회전 간격의 1.2배 이상이며, 같은 알파에서 fit 높이가 두 배가 되면 최소 붓 폭도 두 배가 되는지 확인했다.
- .88 이전에 붓 바깥의 마스크가 0이고, 잔여 마스크는 단조롭게 증가한다. .98에서 붓 안팎 모두 마스크 1이며 리본·펜끝은 0이다.
- 모든 0–255 원본 알파 값에 최종 마스크를 한 번 곱하면 원본 알파 값과 같다. 부분 알파 중첩을 피하는 단일 마스크 합성 식을 검증했다.
- 실제 PNG를 192×175 알파 표본으로 축소하고 경로 세 가지의 리본이 이미지 fit 사각형 안에 있는지 확인했다.
- 잘못된 좌표·진행·경로·알파 크기·해시·MIME·메타데이터를 거절한다. 원본 비율과 64px·128px fit, 정적 위치·기울기·크기도 확인했다.

이 검사는 순수 기하와 마스크 계약을 실행한 결과이다. Compose GPU 픽셀·실제 속도·시각적 매력은 CPU 검사로 승인하지 않았다. 네이티브 빌드, 실제 Android 재생·화면 캡처와 최종 시각 평가는 호스트 통합 담당이 수행한다.

준비 전·정적 복원·이미지 교체에서 콜백이 제외되는 조건과 구간별 1회 플래그는 소스 검토했다. 최소 붓 폭 보정 후 CPU 전용 스크립트를 실행해 전체 PASS를 확인했다. 호스트와의 지연 시작 연동 및 보정한 붓의 실제 화면 결과는 통합 Android 검증 범위다.

## 원본 fixture
