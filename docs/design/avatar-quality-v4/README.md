# 눈티 원화·형상·탄생 효과 v4

2026-11-03. 전체 제품 목표는 운전습관 개선을 돕는 눈티다. 이번 변경은 사용자 담당인 목적지·경로 기반 아바타 생성의 외형·연관성·탄생 효과를 개선한다. 기존 소장품을 새 그림으로 바꾸지 않는다.

## 사용자 피드백과 스타일 기준

1. 이전 v3는 소장 매력과 경로·목적지 연관성이 부족하다는 평가를 받았다.
2. 조사 지침을 적용해 동일 해변 여정의 구조가 다른 A·B·C 원화를 내장 image_gen 도구로 생성했다. 사용자는 세 형태가 모두 괜찮지만 **너무 입체적이고 반투명하다**고 평가했다.
3. 같은 형태를 유지하고 불투명 파스텔 색면·매트 표면·얕은 2.5D 깊이로 편집한 A2·B2·C2에 **지금 표현이 적절함**이라는 응답을 받았다. 이것이 최신 렌더링 스타일 기준이다.

| 현재 원화 | 구조 방향 | 저장 파일 |
|---|---|---|
| A2 | 길에서 자란 몸·감긴 꼬리·부드러운 볏 | [원화](concepts/concept-a-v2.png) |
| B2 | 파도가 감싸는 두 겹의 큰 몸 | [원화](concepts/concept-b-v2.png) |
| C2 | 여정의 공간과 경로를 품은 살아 있는 기념체 | [원화](concepts/concept-c-v2.png) |

세 방향은 아트 디렉션을 비교한 시안이며 앱에서 매번 고르는 고정 캐릭터 목록이 아니다. 이 원화 파일을 새 여정의 생성 결과라고 재사용하지 않는다. 실제 사용한 [첫 프롬프트](concepts/prompts.json), [수정 프롬프트](concepts/edit-v2-prompt.json), [입력 여정](concepts/journey.json), [PNG·SHA 목록](concepts/asset-inventory.json)을 보관했다. 내장 도구의 실제 모델 버전은 공개되지 않아 특정 API 모델의 출력이라고 단정하지 않는다.

현재 승인된 것은 수정 원화의 표현이다. 로컬 코드 렌더·실제 이미지 모델 결과·완성 모션의 소장 의향까지 승인됐다는 뜻은 아니다.

## 생성 구조 변경

이전에는 전체 입력의 해시에서 세 조형과 비율을 선택했다. v4는 [design_intent.py](../../../backend/nunti/avatar_studio/design_intent.py)에서 실제 경로를 분석해 큰 굴곡·주축·시작과 끝의 흐름을 얻고, 몸의 흐름·꼬리·볏을 계획한다. 목적지 특성, 이름에 명시된 단어, 방문 목적의 순서로 창작 근거를 선택한다. 목적지의 이름만 다른 난수를 만드는 방식과 구분한다.

같은 세부 난수에서 경로만 바꾸는 비교와 목적지 정보만 바꾸는 비교로 주요 기하가 달라지는지 검사한다. 새 여정 ID는 세부 변주에 쓰며 입력의 의미를 대체하지 않는다. 실제 원본 선은 별도로 보존하고, 몸으로 해석한 구조는 창작된 대응임을 표시한다. 화면의 커브로 거리·도로·위험도·운전 점수를 추정하지 않는다.

[illustration.py](../../../backend/nunti/avatar_studio/illustration.py)는 새 계획을 실제 RGBA로 그린다. 최신 사용자 피드백을 따라 몸체의 안쪽은 불투명하게 두고 외곽의 안티앨리어싱과 배경에 alpha를 사용한다. 코드 기반의 색면·표정·큰 구조를 시험하는 로컬 렌더다. 내장 이미지 도구 원화와 같은 수준의 미감이나 임의 목적지의 의미 이해를 보장하지 않는다.

## 모션 변경

[formation.js](../../../prototypes/avatar_generator/formation.js)는 열린 경로의 순·역방향에 몸의 외곽을 대응시켜 닫힌 몸체가 실제로 부푸는 형상을 그린다. 완성 PNG의 마스크 폭만 늘리는 방식과 구분한다. 원본 경로를 보여 주는 행렬과 최종 몸체를 크게 보여 주는 행렬을 연속적으로 연결한다. 얼굴·몸체·경로·최종 이미지에 같은 좌표 변환을 적용한다.

LottieFiles motion-design의 원문 지침을 읽고, 한 선을 먼저 보게 하는 staging, 살짝 당겨지는 예비 동작, 몸체 성장, 뒤늦은 상단부 움직임과 안착을 적용했다. 유리 반사·굴절·과도한 glow를 줄이고 얕은 색면으로 물성을 표현한다. Rive를 설치하거나 사용했다고 보고하지 않는다.

새 로컬 결과의 contour·spine이 검증 가능한 때에 이 모션을 사용한다. 이전 소장품은 기존 표시를 유지한다. 외부 API 결과의 실제 기하를 확인하지 않은 경우 로컬 좌표를 그 PNG의 사실처럼 내보내지 않는다.

## 이미지 모델과 비용 경계

유료 API의 구조 지도·원본 경로·스타일 보드를 각각 분리하고, 보존 조건과 목적지 근거를 상세 프롬프트로 준비했다. 최신 불투명 파스텔 표현을 우선하며 PNG alpha는 캐릭터 바깥 배경을 뜻한다. [서버 구현과 검증](server-result.md)에 실제 전송 참조와 승인 게이트를 기록했다.

사용자는 유료 실행 문의에 **원화 선택 후 결정**이라고 답했다. 별도 과금 API는 아직 승인되지 않았고 실제 호출은 0회다. 기본 실행기는 유료 승인 환경을 false로 강제하며, 명시적인 `--paid-api` 없이는 기존 키·예산 설정으로 유료 기능이 열리지 않는다. [보관한 비교 실행안](PAID-EXPERIMENT-PROPOSAL.md)은 실행 승인이 아니다.

무료 로컬 이미지 모델도 앱에 선택 모드로 연결했다. 현재 Mac의 M4 16GiB에서 공개 MLX Community FLUX.2-Klein-4B 4bit를 MFLUX/MLX로 실행한다. 실제 앱의 새 해변 원화는 512px·4step에서 45.01초, MLX 보고 피크 3.49GB였다. 원본 RGB와 모든 참조·seed·revision을 보존하고 외곽 배경 제거 후 RGBA를 만든다. 모델 원본이 투명 PNG인 것은 아니다. 현재 기기에서 수행한 실험이며 다른 환경의 처리량과 미적 품질을 보장하지 않는다. [전체 모델·실패·재현 기록](local-model-result.md)을 참고한다. 기존 음성용 Python 환경은 변경하지 않았다.

## 직접 시험

```sh
cd /Users/pig30nidae/NUNTI
python3 scripts/run_avatar_generator.py --local-ai --restart-server
```

앱에서 **생성 방식 → 로컬 AI · 약 1분**을 선택한다. 경로 사진 또는 시험 경로를 확인하고 목적지·특성·목적을 입력해 생성한다. 위 명령은 유료 API를 활성화하지 않는다. 빠른 코드 렌더와 실제 로컬 AI 생성은 화면에서 구분된다. 같은 경로에서 목적지 특성과 목적을 바꾸고, 같은 목적지에서 다른 경로를 입력해 그림과 설명을 비교할 수 있다. 새 여정과 기존 보관함을 번갈아 열어 identity가 유지되는지도 확인한다.
