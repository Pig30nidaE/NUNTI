# 눈티 V6 200개 상황 검증

`cases.json`은 **20개 목적지 × 10개 방문 목적**을 고정한 재현용 입력이다. 서울역·수원역·을왕리해수욕장은 장소 특성을 따로 입력하지 않아도 이름을 해석하는지 확인한다. 나머지 17곳은 문서에 기록한 장소 특성도 입력한다. 역에 수영하러 가는 조합은 현실의 시설 안내가 아니라 **명시한 목적이 의상을 결정하는지** 확인하는 반사실 시험이다.

## 실행

저장된 매니페스트만 사용하므로 네트워크, 내비 API, 유료 이미지 API가 필요 없다.

```sh
.worktrees/server/backend/.venv/bin/python scripts/verify_avatar_v6_matrix.py
```

다른 Python 환경을 쓸 때는 프로젝트의 backend 의존성을 설치한다. `--limit 3`은 도구 점검용이며 200건 합격으로 처리하지 않는다. 매니페스트를 의도적으로 다시 만들 때만 `--write-manifest`를 사용한다. 이 옵션은 `.local/navigation-integration/live/`의 기존 3개 경로 스냅샷을 읽으며 새 경로를 요청하지 않는다.

## 결과

- `.local/avatar-v6/matrix/index.html`: 200장 전체 갤러리. 방문 목적별 필터와 실제 metadata 링크.
- `.local/avatar-v6/matrix/contact-sheets/`: 25장씩 묶은 8개 시트.
- `.local/avatar-v6/matrix/images/`: 실제 768px RGBA PNG 200장.
- `.local/avatar-v6/matrix/report.json`: 입력 역할 일치, 구조 중복, 실제 픽셀 중복, 근접 이미지 쌍, 실행 소스 해시.
- `.local/avatar-v6/matrix/voice-input.json`: 각 입력과 실제 이미지의 design metadata를 함께 담은 TTS 검증용 자료.
- `.local/avatar-v6/matrix/repeat-control/`: 동일한 을왕리 수영 입력에서 새 여정 10회를 생성한 별도 대조. 같은 요청의 재시도 일치 여부도 확인한다. 이 10장은 200건 수량에 합산하지 않는다.

## 합격 기준과 한계

각 목적지의 10개 목적은 **동일 경로와 동일 세부 seed**로 렌더한다. seed나 색만 달라서 새로운 디자인으로 계산되는 일을 막는다. 경로는 이전에 받은 OSRM 도로 경로 3개에서 만든 20개 합성 QA 변형이다. 원본 출처를 모두 기록하며, 해당 목적지로 가는 실제 길이라고 주장하지 않는다. 실제 내비 연동 검증은 별도다.

검증은 다음을 구분한다.

1. 실제 픽셀이 다른 이미지 수: 파일 이름·PNG 헤더의 차이는 제외한다.
2. 구조가 다른 디자인 수: 몸 형태, 의상 종류·재단, 자세, 행동, 소품, 표정, 바라보는 방향을 비교한다. 색·해시·seed·작은 수치 변형은 제외한다.
3. 근접 중복 후보: DCT pHash 거리, 불투명 실루엣 IoU, 축소한 RGB 차이를 함께 비교한다. 비슷한 실루엣이라는 이유만으로 다른 의상을 중복 처리하지 않는다.
4. 입력 반영: 명시한 방문 목적과 생성 역할이 일치하고, 장소 근거·실제 그리는 부분·모션·음성 역할이 존재하는지 확인한다.
5. 실제 시각 검토: 모든 시트에서 의상·소품이 읽히는지, 장소별 차이가 보이는지, 귀여움과 완성도가 유지되는지 사람이 판단한다.

새 여정 반복 대조는 같은 입력에서 이미지 픽셀뿐 아니라 몸·의상·소품 구조가 달라지는지도 별도로 기록한다. `STRUCTURAL_VARIATION`은 10장이 전부 다른 픽셀이며 구조도 두 종류 이상이라는 뜻이다. 10종 구조가 모두 서로 다른지는 `allTenStructuresDifferent`로 따로 표시한다. 재시도는 PNG와 metadata 모두 같아야 한다.

표정·자세를 제외한 **몸 + 의상 재단 + 소품** 조합 수와, 더 넓게 묶은 **몸 + 의상 종류** 조합 수도 별도로 보고한다. 200개 전체 구조가 달라도 기본 동물형 몸이나 의상을 재사용할 수 있다. 이를 200개의 독립 원화 기본형으로 표현하지 않는다.

`AUTOMATED_DIVERSITY_PASS_VISUAL_REVIEW_REQUIRED`는 자동 기준을 통과했지만 미적 품질 검토가 남았다는 뜻이다. `NEEDS_DIVERSITY_REVIEW`는 렌더가 성공했어도 구조 중복 또는 근접 중복 후보가 있다는 뜻이다. `FAIL`은 입력 반영, 실제 렌더, 수량 중 적어도 하나가 실패한 상태다. **200개 해시가 다르다는 이유로 200개의 완성된 템플릿이라고 보고하지 않는다.**

이 도구는 `LOCAL_RENDER`의 실제 이미지를 만든다. AI 이미지 200회 생성, TTS 200회 합성·청취, 앱 내 모션 200회 재생을 검증했다고 주장하지 않는다. TTS 담당 도구가 만든 실음원 결과와 앱 검증 결과는 별도 보고서로 취합한다. 녹화와 유료 API 호출은 수행하지 않는다.

실제 음원 합성이 끝나면 다음 명령으로 각 이미지와 음성의 역할·이름·프로필·대사·WAV 해시를 검증하고 갤러리에 재생 컨트롤을 붙인다. 눌렀을 때만 재생한다.

```sh
.worktrees/server/backend/.venv/bin/python scripts/verify_avatar_v6_matrix.py \
  --attach-voices .local/avatar-v6/voices-final/results.json
```

최종 음원은 `voices-final/`을 사용한다. `voices/`는 초기 실패·과긴 발화 후보를 보존한 비교 증거이며 테스트용 최종 음원 목록이 아니다.

실제 AI 이미지 검증은 사용자 요청으로 30개를 선정해 별도로 실행했다. 선정안은 `ai-cases-30.json`, 실행 안내는 `AI_MATRIX.ko.md`, 최종 결과 갤러리는 `.local/avatar-v6/ai-matrix-selected/index.html`이다. 입력 플랜에 20개 목적지, 시험 목적 10종 각 3건, 몸 형태 12종 각 2~3건을 포함한다. 모델이 그린 동물종이 계획과 같은지는 실제 이미지에서 따로 검토한다. 첫 결과와 재검증을 포함한 행렬 실험 모델 시도는 37회이며 원본·실패는 보존했다. 이 30장의 실제 AI 결과와 절차형 200장을 합쳐서 "AI 생성 200장"으로 보고하지 않는다.

`visual-review.json`의 검토자는 Codex AI다. 실제 시트를 보고 의상·장소 소품·얼굴 가림을 확인한 기록이며, 사용자나 사람 심사자의 미적 품질 승인으로 표시하지 않는다. 자연스러움과 귀여움에 대한 음성 청취 평가, 소장 욕구, 운전 습관 개선 효과는 별도 검증이 필요하다.
