# 목적지와 방문 이유로 눈티를 만들고 목소리 듣기

준비된 Mac과 Pleos 에뮬레이터에서 직접 테스트할 때 다시 실행한다. 이미지와 음성은 Mac의 로컬 모델이 만든다. API 계정이나 키는 필요 없다. 테스트하는 동안 Mac과 필요한 로컬 서버를 켜 둔다.

## 앱 열기

저장소 루트에서 실행한다.

```sh
cd /Users/pig30nidae/NUNTI
python3 scripts/run_avatar_generator.py --local-ai --navigation-api --restart-server
```

실제 Android 앱이 열린다. 차량은 P, 속도는 0이어야 한다. 이미 앱이 열려 있다면 명령을 반복할 필요가 없다.

앱이 숨겨지면 [Pleos 차량 콘솔](http://127.0.0.1:8088/)을 열어 유지하고 P·정차·차량 화면 사용 허가를 확인한다. 내비가 연결됐다고 표시돼도 목적지가 들어오지 않으면 [재시작 대화상자 처리](../navigation-integration/TESTING.ko.md#에뮬레이터-재시작-후-내비가-응답하지-않을-때)를 따른다.

## 내비 경로로 만들기

1. **현대 내비 열기**를 누른다. 내비 앱에서 목적지를 설정한다.
2. 눈티 앱으로 돌아와 **내비 목적지 불러오기**를 누른다.
3. **경로 API로 길 불러오기**를 누른다. 표시된 출발지·목적지와 전체 선을 확인한다.
4. **이번에 가는 이유**에 구체적인 활동을 입력한다.
5. 경로 확인란을 체크하고 **이 길에서 눈티 만나기**를 누른다.
6. 탄생이 끝나면 **이 눈티의 목소리** 옆 재생 버튼을 누른다.

로컬 AI 이미지는 현재 Mac에서 약 1분 걸린다. 첫 음성은 모델 준비 후 합성하며 이후에는 저장 음원을 바로 재생한다. 생성된 그림과 음성은 자동으로 보관된다. 새 여정을 만들면 새 캐릭터를 만들고, **내 눈티**에서 다시 열면 저장한 캐릭터를 복원한다.

현대 SDK는 목적지·현재 위치·경로 상태를 제공한다. 화면의 전체 도로 선은 별도 OSRM API에서 가져온다. 현대 내비가 선택한 경로와 같다고 보장하지 않는다. [내비 연결 안내](../navigation-integration/TESTING.ko.md)에 좌표 입력과 저장 경로 재사용 방법이 있다.

## 목적 차이를 빠르게 비교하기

하단의 여정 입력 예시를 선택하면 합성 시험 경로가 채워진다. 실제 목적지까지의 도로 안내로 사용하지 않는다. 이 상태에서 목적지와 방문 이유를 바꿔 아래 조합을 비교한다. 이미지 생성 방식에서 **빠른 일러스트**를 선택하면 AI 추론 대기 없이 의상·소품 차이를 볼 수 있다.

| 목적지 | 방문 이유 | 확인할 차이 |
|---|---|---|
| 서울역 | 출장 회의에서 발표하기 | 정장, 업무 소품, 시계 모양 기념 가방, 자신감 있는 목소리 |
| 서울역 | 조용히 쉬고 싶어요 | 느슨한 니트, 휴식 소품, 포근한 목소리 |
| 수원역 | 연인과 데이트 | 리본 칼라, 꽃 등 데이트 소품, 기차 모양 가방 |
| 을왕리 해수욕장 | 수영과 물놀이 | 수영복, 수경, 수영 자세, 조개 가방, 밝고 장난스러운 목소리 |
| 을왕리 해수욕장 | 거래처 미팅 출장 | 해변 기념 가방을 지닌 정장 캐릭터 |
| 안목해변 | 어린이 캐릭터가 해변에서 책 읽기 | 독서 의상·책 소품·조개 가방, 앳된 독서 동반자 음성 지시 |

AI가 제안한 의상·소품을 그대로 그렸는지도 확인한다. 구체적인 뜻을 해석하지 못한 방문 이유는 기본 여행복으로 표시하고, 해석하지 못했다는 안내를 보여 준다.

## 검증한 그림과 목소리 비교하기

실제 AI 30개와 연결된 목소리:

```sh
open .local/avatar-v6/ai-matrix-selected/index.html
```

빠른 일러스트와 실제 음원 200개:

```sh
open .local/avatar-v6/matrix/index.html
```

방문 목적별로 필터를 적용하고 각 카드의 재생 버튼으로 실제 음성을 듣는다. 이는 시험 결과 모음이며 실제 생성기가 이 목록에서 완성 캐릭터를 고르는 방식은 아니다. AI 30개는 재시도 7회를 포함해 선택했으며 세부 소품의 생성 편차는 [결과 보고](RESULT.ko.md)에 남겼다.

## 연결이 끊기거나 생성이 기다려질 때

- 서버 연결 화면이면 위 실행 명령을 다시 실행한다.
- 다른 이미지나 음성을 만들고 있다는 안내가 나오면 해당 작업이 끝난 뒤 같은 버튼을 다시 누른다. Mac의 이미지·음성 추론은 GPU를 차례로 사용한다.
- 그림의 배경·형태 검사에서 거절되면 같은 생성 버튼으로 새 그림을 시도할 수 있다. 실패 원본은 검증용으로 보존하며 보관함의 완성 캐릭터로 표시하지 않는다. 네트워크 결과가 불확실하거나 유료 API를 사용한 요청은 임의로 새 요청으로 바꾸지 않는다.
- 음성은 준비됐지만 브라우저가 재생을 막으면 재생 버튼을 다시 누른다.
- 저장 음원이나 그림이 바뀌었다는 오류가 나오면 파일을 덮어쓰지 않는다. 오류와 해당 캐릭터 ID를 확인한다.

다른 컴퓨터의 모델 설치는 [이미지 환경](../avatar-quality-v4/local-model-result.md)과 [음성 환경](VOICE.ko.md)을 참고한다. 실행 도구는 영상이나 오디오를 녹화하지 않는다.

## 테스트를 마친 뒤

사용자가 명시적으로 종료를 요청할 때만 관련 로컬 서버·이미지 및 TTS 모델 프로세스·에뮬레이터·VSCode를 정상 종료한다. 작업이나 검증이 끝났다는 이유로 자동 종료하지 않는다. 미저장 편집을 강제로 폐기하지 않는다.
