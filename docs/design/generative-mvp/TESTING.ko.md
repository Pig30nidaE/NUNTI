# API 키 없이 Nunti 생성 MVP 시험하기

현재 시험본은 목적지·경로 입력부터 이미지 표시, 음성 재생, 새 대사 연결, 도착·보관·복원까지 실행한다. 화면의 **샘플 미디어로 연결 시험 중** 표시는 유지된다. 입력에 따라 새 이미지나 새 음색을 생성하는 품질 시험은 API 연결 후 진행한다.

현재 연출과 검증 결과는 [경로가 몸체가 되는 탄생 연출](route-formation.md)을 따른다. 이전 원형 공개 방식의 [최초 연결 시연 기록](demo/README.ko.md)도 보존한다.

## 앱 열기

복원된 이 Mac의 터미널에서 실행한다.

```sh
cd /Users/pig30nidae/NUNTI
python3 scripts/run_generative_mvp.py
```

도구가 로컬 서버와 별도 작업자를 확인하고 Pleos 에뮬레이터에 APK를 설치한다. 공급자 계정·키·추가 모델 다운로드는 사용하지 않는다. 새 입력마다 앱을 다시 설치할 필요가 없다.

APK를 다시 빌드하려면 다음 명령을 사용한다. 복원된 JDK·SDK·Gradle 캐시를 사용한다.

```sh
python3 scripts/run_generative_mvp.py --build
```

파일과 환경만 확인하려면 `--check`를 사용한다. 서버 코드 변경 후에는 `--restart-server`로 이 도구가 시작한 v2 서버와 작업자를 다시 시작한다. 기존 로컬 Sohee 작업자는 별도 포트에서 유지된다.

## 목적지에서 동반자 만나기

1. 화면의 주차 상태가 **P**인지 확인한다.
2. 목적지, 그곳의 느낌, 여행 목적을 입력한다.
3. 왼쪽 경로 영역에 선을 이어 그린다.
4. **동반자 만나기**를 누른다.
5. 경로·빛·이미지 공개 연출과 샘플 표시를 확인한다.
6. **음성 시험 시작**을 누른다.
7. **인사 듣기** 또는 **응원 듣기**를 누른다.
8. 재생 중 **중지**를 눌러 취소를 확인한다.

현재 샘플은 기존 해안 캐릭터 PNG와 기존 Sohee WAV다. 입력 목적지가 달라도 이미지와 대사에 그 목적지가 새로 반영되는 것은 아니다. 원본 출처와 실제 본문은 서버 아티팩트의 `fixtureProvenance`에 보존된다.

같은 문장은 재생 시작 후 60초 동안 반복 재생이 억제된다. 음성이 나오지 않으면 다른 문장을 선택하거나 잠시 후 다시 듣는다. 생성·복원 직후에는 음성을 자동으로 재생하지 않는다.

## 같은 목소리의 후속 대사 연결 시험하기

샘플 모드에서는 이미 등록된 본문만 사용할 수 있다. **같은 목소리로 새 대사**에 다음 본문을 붙여 넣는다.

```text
산을 만나러 가는 날이네. 어떤 작은 발견이 기다릴까?
```

1. **대사 준비**를 누른다.
2. 준비 완료 안내를 기다린다.
3. **새 대사 듣기**를 누른다.

이 시험은 같은 캐릭터 바인딩에 새 음원을 추가하는 동작을 확인한다. 새 문장에 대한 실제 모델 합성이나 새 음색의 자연스러움을 검증하지 않는다. 등록되지 않은 본문은 샘플 모드에서 거절한다.

## 소장품 복원 시험하기

1. **도착했어요**를 누른다.
2. 버튼이 **도착 대사**로 바뀌면 눌러 세 번째 초기 음원을 확인한다.
3. **동반자 보관**을 누른다.
4. 앱을 종료한 뒤 실행 도구로 다시 연다.
5. 같은 이미지와 소장품 이름이 복원되는지 확인한다.
6. 음성이 자동 재생되지 않고 음성 시험 확인이 해제되는지 확인한다.
7. **음성 시험 시작**을 다시 누른 뒤 기존 대사와 **새 대사 듣기**로 저장한 음원의 복원을 확인한다.

## 자동 검증 실행하기

동영상 녹화와 스피커 녹음은 사용자가 명시적으로 요청한 경우에만 실행한다. 아래 일반 검증은 녹화하지 않으며, 화면 이미지 저장도 생략하려면 `--no-screenshots`를 사용한다.

앱과 샘플 서버가 실행 중일 때 다음 명령을 사용한다. 별도의 validation 보관함에서 실제 HTTP·Android JSON·PNG·WAV·재생·취소·복원을 시험한다.

```sh
python3 scripts/verify_generative_mvp.py
```

검증 기록은 `.local/generative-mvp/native-<시각>/`에 저장한다. 이 명령은 시험 중 에뮬레이터 화면을 조작하므로 수동 시험과 동시에 실행하지 않는다.

사용자가 스피커 녹음을 요청한 경우에는 다음 명령으로 실제 입력란·경로 터치·생성/듣기 버튼과 PCM을 함께 확인한다. PCM 기록은 음성 출력 신호의 증거이며 사람의 청취 평가는 아니다.

```sh
python3 scripts/verify_generative_ui.py --record-speaker
```

사용자가 영상 녹화까지 요청한 경우에는 `--record-video`를 추가한다. 결과 폴더에 Android 화면 원본 MP4와 같은 실행의 speaker WAV·packet 시각을 보관한다. macOS에서 다음 도구로 음성을 합친다. 출력 경로는 아직 없는 새 파일을 지정한다.

```sh
python3 scripts/verify_generative_ui.py --record-speaker --record-video
python3 scripts/export_generative_demo.py .local/generative-mvp/touch-실행시각 --output .local/generative-mvp/새시연.mp4
```

`touch-실행시각`은 앞 명령이 출력한 실제 폴더로 바꾼다. 내보내기는 설치된 Swift·AVFoundation을 사용하며 추가 다운로드는 없다. 원본 영상 압축 sample을 보존하고 packet 시각 사이의 무음만 채운 실제 speaker PCM을 AAC로 넣는다. 시각 동기화는 근삿값이며 지연 측정에 사용하지 않는다.

전달 APK와 설치 APK의 일치, 저장된 시험 근거의 해시, 인증 미디어, 같은 요청의 재시도 불변성을 재확인하려면 다음 명령을 사용한다.

```sh
python3 scripts/verify_generative_delivery.py --live
```

현재 완료 결과와 제한은 [검증 보고](test-report.md)에 정리했다. 자동 시험 후 수동 시험을 시작할 때는 `python3 scripts/run_generative_mvp.py`로 일반 보관함을 다시 연다.

모델 비교 입력 준비와 블라인드 평가 절차는 [벤치마크 안내](benchmark/README.ko.md)를 따른다. 20개는 시험 입력 수이며 내부적으로 모델 비교를 위해 최대 26개 결과를 받을 수 있다. API 품질을 시험할 때는 각 파이프라인의 서버·저장소를 분리하고 비교 비용을 합산한다.

## API 연결 전 확인할 항목

서버 API 어댑터는 구현돼 있지만 실제 계정의 모델 접근, Voice Design 비용, 슬롯과 속도는 아직 확인하지 않았다. 계정이 준비되면 [API 키 발급·설정 안내](API-SETUP.ko.md)에서 환경파일·비용 상한·실행 전 검사 순서로 연결한다. [서버 운영 안내](../../../backend/README.md)에 별도 작업자와 실비 정산 절차가 있다. 키를 APK나 채팅에 넣지 않는다.

키가 없는 API 모드는 `MISSING_PROVIDER_CREDENTIALS`로 중단한다. 샘플이나 Sohee로 자동 대체하지 않는다. 실제 생성 품질·한국어 자연스러움·소장 의향·비용은 API 비교와 사용자 청취 평가가 끝난 후 보고한다.
