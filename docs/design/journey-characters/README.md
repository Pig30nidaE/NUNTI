# 여정에서 태어나는 반투명 동반자

최신 생성 흐름은 [목적지·경로에서 동반자가 태어나는 시험본](../route-birth/test-report.md)을 따른다. 앱에서 목적지·특성·목적과 직접 그린 경로를 입력하면, 기존16윤곽 선택 없이 새72점 외형과 로컬 Sohee 음성을 생성한다. 경로 trace→몸체 morph→얼굴 등장, 런타임 음원 수신, 도착·보관·복원을 연결했다. 새5여정·15새WAV는 검증 표본이며 선택지나 생성 상한이 아니다. PC 모델/로컬 bridge가 필요하고 외부 API·계정은 사용하지 않는다. Anna 선호는 유지한다. 지도·내비 입력·폭넓은 자유 서술 해석·Android 추론·실차·사람의 품질 평가는 남았다. 아래8개 목록 방식은 이전 검증본이다.

2026-11-02 PM 설계. 사용자 선택은 **C · 반투명 기념 오브젝트**다. 목적지·경로·목적지 특성·방문 목적에서 매번 새로운 2.5D 캐릭터를 만들고, 그 캐릭터에 맞는 목소리를 함께 보존한다. 한 세계관 안에서 몸 자체가 다른 생명이 태어나는 경험을 목표로 한다.

비교 이미지·여정 레시피·담당 설계에 이어 실제 로컬 TTS와 Android Debug 재생을 구현했다. 사용자의 "전체적으로 더 작고 귀여운 느낌" 피드백은 F3/F4/F5와 길이 보존 +3반음의 v2 청취 후보에 반영했다. [세 음성 비교](../../../prototypes/journey_voice/listen-v2.html)와 [최신 구현·시험 보고](tts-result.md)를 따른다. 아래 목표 설계 중 자동 이미지 생성·새 2.5D renderer·컬렉션은 아직 미구현이다.

## 사용자 선택과 디자인 기준

[C 원안](concepts/c-luminous.png)을 사용자가 선택했다. [C 수정안](concepts/c-luminous-v2.png)은 PM이 반투명 재질을 통일하고 해안의 낮은 물결형, 산악의 세로 배형, 전시의 넓은 별형으로 몸을 구분한 탐색 결과다. 세부 형태의 사용자 수용이나 품질 평가는 아직 하지 않았다.

세 캐릭터 비교 시안은 같은 합성 여정으로 별도 제작한 아트 탐색이다. 별도로 [해안 레시피 단독 시안](concepts/recipe-coastal-001.png)은 실제 CLI JSON에서 [프롬프트 변환기](../../../prototypes/journey_characters/build_illustration_prompt.py)로 만든 문장을 내장 image_gen에 전달해 생성했다. 레시피→프롬프트→정적 그림 한 장의 제작 경로를 시험했으며, 앱의 자동 생성 연결은 아니다.

![C 방향 수정 시안](concepts/c-luminous-v2.png)

소장 욕구를 만드는 핵심은 그 여행에서만 만났다고 느끼는 몸과 표정, 기억이다. 투명 유리의 복잡한 반사보다 부드러운 반투명 덩어리, 불투명한 얼굴, 절제된 내부 빛을 우선한다. 눈·입은 작은 화면에서도 읽혀야 한다. 모든 캐릭터에 같은 얼굴을 붙인 뒤 껍질만 바꾸지 않는다.

비교용 [A](concepts/a-soft-sculpt.png), [B](concepts/b-plush.png), [D](concepts/d-plush-morphology.png)는 탐색 기록으로 남긴다. D는 사용자 선택 전에 만든 봉제 방향 수정안이며 채택안이 아니다. [리뷰](review/product-art-review.md)의 이전 B 추천보다 사용자의 C 선택이 우선한다.

## 입력이 캐릭터가 되는 방식

아래는 목표 설계다. 프로토타입의 실제 필드는 [실행 가이드](../../../prototypes/journey_characters/README.md)를 따른다.

| 입력 | 창작에 반영할 요소 | 예시와 경계 |
| --- | --- | --- |
| 목적지 유형·사용자 선택 분위기 | 몸의 모티브, 재질, 기본 색 | 해안 분위기 → 낮은 물결 몸·서리 낀 아쿠아. 실제 해안 도로 통과를 뜻하지 않음 |
| 경로의 확인 가능한 특징 | 몸의 비례, 내부 선의 배열·겹침 | 여러 구간을 지난다는 창작 표현. 정밀 이동 궤적을 자동 새기지 않음 |
| 방문 목적 | 성격·표정·내부 빛·voiceIntent | 휴식 → 여유로운 표정과 말하기 의도. 미입력 목적은 UNSPECIFIED |
| 소장 이력 | 최근 몸체·얼굴·재질 반복 억제 | 새 이름·색·ID만 달라진 결과를 충분한 개별성으로 세지 않음 |
| 생성 예약과 버전 | 한 여행의 외형·목소리 정체성 보존 | 새 여행은 새 ID. 재시도·reroute·재시작은 최초 확정 결과 재사용 |

사용자 목적·분위기와 검증된 도로·운전 사실은 별도 입력이다. 예를 들어 “바다에서 쉬고 싶은 날”은 물결 모티브의 근거가 될 수 있지만 해안도로 검증이나 좋은 운전 판정의 근거는 아니다. 실제 이벤트와 점수·최종 코멘트의 소유권은 기존 모듈에 남긴다. 외부 payload·담당 협의는 사용자 지시에 따라 보류한다.

## 생성 파이프라인

1. 앱은 새 여행 행동에서 여정 ID, characterId, generationId, seed와 입력 snapshot을 먼저 영속화한다. 제품에서는 기존 tripId를 여정 ID로 사용하고 별도 journeyId를 중복 도입하지 않는 안을 따른다. 실험 CLI의 journeyId는 이 개념을 나타내는 독립 이름이다.
2. 창작기는 모티브·몸체 구조·비례·얼굴·반투명 재질·내부 무늬·빛·성격·이름 방향·voiceIntent를 담은 레시피 후보를 만든다. 운전 사실이나 최종 코멘트를 만들지 않는다.
3. 아트디렉터는 허용 세계관·얼굴 보호·레이어 호환을 먼저 검사한다. 그 뒤 소장 이력과 비교해 구조적으로 가까운 후보를 줄인다. 새 ID나 다른 해시만으로 통과시키지 않는다.
4. 일러스트레이터 모델은 레시피와 C 참조 이미지로 후보를 만든다. 원본 한 장을 얻은 뒤 표정·레이어·rig·작은 화면을 별도로 검수한다. 한 장의 좋은 그림이 애니메이션 가능한 자산이라는 뜻은 아니다.
5. TTS는 성격 의도를 실제 검수한 한국어 음성 목록에 매핑한다. 캐릭터와 시각 자산·voice binding을 하나의 불변 선택 결과로 묶는다. 모델이 임의 화자 ID나 미지원 제어를 만들어 적용하지 못하게 한다.
6. 출발 전 확정한 결과와 실제 자산 바이트·해시·버전을 저장한다. 이동 중에는 교체하지 않는다. 도착 후 주차가 확인되면 같은 캐릭터에 추억을 남기고 컬렉션 보관을 선택한다.

같은 경로로 다음 여행을 시작해도 새 캐릭터를 만들 수 있다. 같은 여행의 HTTP 재전송·경로 변경·앱 재시작은 새 여행이 아니다. 원격 후보가 출발 후 완성돼도 현재 외형·화자를 바꾸거나 자동 공개·발화·수집하지 않는다. seed만으로 원격 모델의 같은 이미지 바이트를 복원할 수 없으므로 선택한 실제 파일이 복원의 기준이다.

생성 대기 때문에 출발을 막지 않는다. 목표 구조는 검수된 여러 체형으로 로컬 후보를 즉시 준비하고 원격 생성을 비동기로 추가하는 방식이다. 로컬 자산도 저장도 준비되지 않았으면 명시적인 준비 실패를 보여 주며, 저장하지 않은 캐릭터의 재시작 복원을 보장하지 않는다.

## 생성 방식의 선택

| 방식 | 판단 |
| --- | --- |
| 고정 파츠만 조합 | 오프라인 시작과 품질 통제에 유리. 현재 CLI가 증명하는 범위다. 유한 조합이라 이 방식만으로 매번 기대 이상의 새 디자인을 약속할 수 없음 |
| 제약 없는 매번 이미지 생성 | 형태 탐색은 넓지만 표정·세계관·반투명 경계·rig 일관성을 보장하지 못함. 그림 한 장을 바로 앱에 투입하지 않음 |
| C의 아트 규칙을 둔 생성 + 검수 자산 대체 | 목표로 선택. 전문 창작 모델이 몸·재질을 탐색하고, 허용 디자인·표정·rig·음성 목록과 품질 검사가 결과를 제한. 오프라인과 실패 시 검수 자산 사용 |

현재 이미지는 내장 image_gen으로 생성했다. 세부 모델명을 추정해 기록하지 않는다. 앱용 공급자·애니메이션 도구·운영 비용·지연·권리 조건은 선정 또는 실측하지 않았다. 프롬프트 역할을 [생성 프롬프트](generation-prompts.md)로 분리했으며 실제 이미지 생성에 사용한 전체 문장은 [image-prompts.json](image-prompts.json)에 보존했다.

## 2.5D와 목소리의 구현 경계

2.5D 목표는 고정 시점의 입체적인 그림과 깊이가 다른 레이어, 체형별 표정·미세 동작이다. 반투명 외피·내부 모티브·얼굴·하이라이트·그림자는 순서와 alpha 규격을 가진 자산으로 만든다. 비교 시안은 배경이 포함된 단일 PNG다. 해안 단독 시안은 실제 투명 alpha를 확인했지만 역시 단일 PNG이며 레이어·rig 자산이 아니다. 첫 제품 실험은 세 체형과 6개 정적 표정부터 시작하고, 눈깜박임·호흡·인사는 별도 정책·렌더링 검증 뒤 추가한다. 현재 정책의 animationsAllowed=false를 그림 생성으로 열지 않는다.

음성은 캐릭터마다 성격에 맞게 달라지되 같은 캐릭터는 화자를 유지한다. 전 캐릭터가 영구적으로 유일한 음색을 갖는다는 요구로 확대하지 않는다. 한국어 발음·자연스러움·외형 적합성을 청취한 유한 화자군에서 선택하고 리듬·표현 preset을 묶는 안이다. 반투명 캐릭터라고 모두 높은 피치나 속삭임으로 만들지 않는다.

기존 Pleos 어댑터는 locale과 기본 화자만 사용한다. 새 실험은 PC의 Supertonic3 합성 WAV를 `LocalFileTtsProvider`와 `AndroidLocalAudioPlayer`로 재생하며 캐릭터·profile·speaker·정확한 원문과 파일 hash를 고정한다. 기존 단일 정책·큐·포커스를 공유하고 누락·손상·미등록 음성을 기본 화자로 대체하지 않는다. 이 경로는 Debug 진단이며 Android 내 모델 합성은 아니다. 공식 바이너리에 speaker 선택 메서드는 있지만 허용 값과 한국어 품질을 확인하지 않았다. 희망 voiceIntent는 실제 음색 변화가 아니다. 별도 player와 공급자를 연결하더라도 기존 발화 허가·단일 큐·포커스·TTL·취소 소유자를 유지한다. 음성 복원은 과거 발화를 다시 재생하는 일이 아니다. 원문 finalText를 캐릭터 말투로 다시 쓰지 않는다.

오프라인에 같은 캐릭터·같은 문장의 승인 오디오가 있으면 사용할 수 있다. 없으면 준비 대기 또는 무음으로 처리하고 임의 화자로 몰래 바꾸지 않는다. 생성·합성·재생·동기화 동의는 목적에 맞게 분리한다. 현재 주행 기록의 30일 만료와 오래 소장할 캐릭터의 보관 수명도 별도 설계가 필요하다.

## 소장 경험과 운전습관 가설

출발 전에 이번 여행의 작은 동반자를 만나고, 도착 후 그 캐릭터가 기억하는 한 장면을 남긴다. 이전 컬렉션은 날짜·이름·허용된 최소 기억으로 다시 만난다. 매번 뽑기를 조작하는 피로를 줄이기 위해 기본 후보로 바로 출발할 수 있게 한다.

검증된 긍정 행동의 회고는 도착 후 전달한다. 캐릭터를 죽이거나 빼앗고 죄책감을 주는 방식, 주행거리·속도·운전 횟수에 희귀 보상을 연결하는 방식은 쓰지 않는다. 운전 중 수집 조작도 요구하지 않는다. 내부 빛은 창작 표현이며 운전 점수나 위험도 표시가 아니다.

귀여움·소장 의향과 운전습관 개선은 서로 다른 검증이다. 먼저 같은 여행의 여러 후보를 무작위 순서로 보여 주고 귀여움, 갖고 싶은 정도, 여행 연관성, 다른 캐릭터와의 구별을 각각 묻는다. 이후 같은 피드백에 캐릭터가 있는 조건과 없는 조건을 비교해 검증 이벤트를 주행 노출량에 맞춰 평가해야 한다. 현재 디자인이나 17개 자동 검사로 행동 개선을 입증하지 않는다.
