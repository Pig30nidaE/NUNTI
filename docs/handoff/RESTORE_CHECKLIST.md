# 담당별 복원 보고 절차

2026-11-02 PM 복원 작업에 공통으로 적용한다. 과거 보고 원문은 수정하지 않는다.

1. 배정된 독립 worktree에서 담당 시작 프롬프트와 연결된 문서를 읽는다. HEAD·branch·변경 파일과 실제 도구 버전을 확인한다.
2. `python3 scripts/verify_handoff.py --output <증거 경로>`를 실행한다. 이 결과는 문서·과거 증거 무결성에 한정한다.
3. RELOCATION.md의 해당 담당 검사를 실제 실행한다. 의존성은 고정 버전을 유지한다. 설치 파일과 캐시는 해당 worktree의 `.local/` 또는 PM이 지정한 역할별 경로에 둔다.
4. 실제 실행한 명령·시각·종료 코드·로그를 보존한다. 실패 원인과 미실행 항목을 구분하고 과거 통과를 새 통과로 재사용하지 않는다. 토큰·비밀값은 기록하지 않는다.
5. `docs/handoff/restoration/2026-11-02/<역할>.md`와 같은 경로의 역할별 증거 폴더에 결과를 남긴다. 완료·미구현·미검증·환경 차이·차단사항·다음 첫 작업·완료 기준을 적는다.
6. 담당 소유 파일만 수정한다. 공통 Gradle·app host·wire 변경은 PM과 먼저 조율한다. 이번 범위는 환경 복원·기준선 검증·다음 작업 조율이다.
7. 다른 담당의 폴더·index·도구 설치 경로에는 쓰지 않는다. 공유할 도구는 설치 담당이 완료를 알린 뒤 읽기 전용으로 사용한다. PM 통합 폴더의 보고서는 PM이 취합한다.

외부 서비스에 메시지를 보내거나 실차·운영 배포를 실행하지 않는다. 앱 실행 검증은 통제된 로컬 에뮬레이터 조건을 확인한 뒤 별도로 수행한다.
