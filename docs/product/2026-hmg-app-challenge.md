# 2026 현대자동차그룹 공모전과 Nunti의 역할

확인일: 2026-11-03, Asia/Seoul. 공식 공모전 홈페이지·참가 가이드·FAQ·공지와 현행 Pleos 개발 문서를 대조했다. 이 문서는 제품 범위와 다음 구현의 기준이며, 아래 미구현 항목이 완료됐다는 보고가 아니다.

## 전체 제품 목표와 사용자 담당 기능

**눈티(Nunti)는 운전습관 개선을 도와주는 아바타 동반자다.** 사용자 담당은 이 제품 안의 **목적지·내비게이션 경로 기반 아바타 생성 기능**이다. 경로와 이동 목적을 반영한 나만의 눈티를 만들어, 주행 이벤트에 따른 감정·음성 피드백에 애착과 연속성을 더하는 역할이다.

| 구분 | 목표와 책임 |
|---|---|
| 전체 제품 | 눈티의 반응과 피드백을 통해 운전자가 자신의 운전습관을 돌아보고 개선하도록 지원 |
| 사용자 담당 기능 | 목적지·경로·목적지 특성·방문 목적으로 귀엽고 소장하고 싶은 2.5D 아바타와 어울리는 음성 정체성을 생성·보존 |
| 연결되는 모듈 | 주행 이벤트·점수·최종 코멘트, 감정 상태와 피드백 정책, 아바타 표시·TTS 재생. 각 모듈의 책임과 검증된 입력을 유지 |

제품의 목표 흐름은 **여정 입력 → 개인화된 눈티 생성 → 검증된 주행 이벤트에 따른 감정·음성 피드백 → 운전습관 개선 지원**이다. 이 흐름의 전체 통합이나 실제 개선 효과가 이번 검토에서 검증됐다는 뜻은 아니다. 생성 모듈이 경로의 모양으로 운전 점수나 안전성을 산정하지 않는다.

입력은 내비게이션이 계산한 목적지행 경로다. 출발 전 선택 경로와 실제로 지나간 주행 기록도 구분한다. 손그림은 기존 개발 진단과 경로선 보정 도구이며 제품의 기본 입력이 아니다. 내비게이션 앱 자체, 도로 탐색 엔진, 외부 담당의 운전 점수 산정까지 우리 모듈에서 새로 만들지 않는다.

목적지의 특성·방문 목적을 창작 재료로 사용하고, 경로의 어떤 특징이 몸체·곡선·무늬·소품에 반영됐는지 설명한다. 사용자가 고른 C 방향, 반투명 기념 오브젝트와 귀여움·소장 욕구를 유지한다. 매 새 여정은 새 아바타를 만들되 같은 요청의 재시도·복원·동일 여정 재탐색은 확정한 정체성을 보존한다. 생성 UUID만으로 전 세계의 시각적 유일성을 보증하지 않는다.

담당 생성 기능의 기본 경험은 다음과 같다.

> 목적지·내비 경로 불러오기 → 여정과 생성 모티브 확인 → 경로에서 아바타 탄생 → 원래 경로와 아바타를 함께 확인

생성 결과의 캐릭터 ID·설정·외형과 준비된 음색 바인딩을 감정·피드백·표시·TTS 모듈에서 이어서 사용하도록 한다. 여정 중의 감정 변화가 확정한 외형·음색 정체성을 새로 생성하거나 바꾸게 해서는 안 된다. 구체적인 이벤트 payload와 담당 조율은 기존 보류를 유지한다.

캐릭터별 TTS와 수집 경험은 제품의 애착·피드백 경험에 포함된다. 음성 생성 실패나 음성 슬롯 부족 때문에 완성된 아바타까지 못 보게 하는 준비 계약은 분리해야 한다. 이는 담당 생성 파이프라인의 준비 상태를 나누는 설계이며 전체 제품의 음성 피드백을 후순위로 정하는 결정이 아니다. 리본 연출은 생성 결과를 공개하는 수단이며 경로가 그림에 반영됐다는 검증을 대신하지 않는다.

운전습관 개선 지원은 확정된 제품 목표다. 눈티에 대한 애착과 피드백이 실제 행동 개선으로 이어지는지는 미검증이며, 이미지 품질·귀여움·소장 의향만으로 그 효과를 입증하지 않는다.

## 현대가 제공하는 기능과 경계

### NaviHelper

2026-11-04 후속 검토에서 실제 에뮬레이터 내비의 더현대서울27km/30분 탐색과 SDK 소스까지 확인했다. `TripSummary.routePoints`는 경유지·목적지 요약점이며 전체 도로 굴곡이 아니다. 문서화된 공개 SDK에서 전체 polyline 반환 경로는 찾지 못했다. 목적지·상태 SDK 연동과 전체 경로 형상 획득을 구분한다. 실제 경로 사진은15점을 반환했으나 일부 대안 경로가 섞여 보강이 필요했다. [실제 검토·권장 시험 순서](../research/2026-11-04-navigation-review/README.md)를 우선한다. 아래는 11월3일 당시 확인 이력이다.

NaviHelper v3.0.5는 목적지·경유지, 경로 옵션·재탐색, 내비 정보·화면 요청과 이벤트를 제공한다. 목적지·탐색 이벤트의 API는 확인했지만, Nunti가 필요한 전체 경로 polyline의 필드·좌표계·전체/잔여 구간 의미는 아직 실 payload로 검증하지 못했다. [공식 소개](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/intro)

이 확인 전에는 내비 경로 화면 이미지 또는 확인된 좌표 JSON을 시험 입력으로 사용한다. v3는 사진을 불러와 색상 경로선을 추출하고 원본 위에 보여 주며 사용자 확인을 받는다. 모호하면 다른 색상·사진·좌표 파일을 선택한다. 현재 화면에서 임의로 점을 드래그해 보정하는 기능은 없다. 화면 좌표를 GPS·거리·도로 종류로 오인하지 않는다. 제공한 세 시험 사진은 실제 지도 데이터가 없는 합성 예시다. [v3 직접 시험](../design/avatar-generator/TESTING.ko.md)

별도 지도 표시가 필요하면 MapLibre를, 별도 경로 계산이 필요하면 OSRM·Valhalla·GraphHopper를 검토할 수 있다. 둘의 역할은 다르다. 지금 턴바이턴 내비를 만드는 일부터 시작하지 않는다. [내비 입력 조사](../research/2026-11-03-navigation-input.md)

### Gleo AI

공모전 맥락에서 검토할 제품은 현대의 **Gleo AI, 글레오 AI**다. 기존 LLM SDK는 2026-10-19 종료됐으며, 현행 문서는 Gleo Interface를 안내한다. [공식 변경 이력](https://document.pleos.ai/en/docs/pleos-only/release-note/playground-release-note)

Gleo Interface는 음성 명령으로 앱의 등록 함수를 호출하고 앱의 응답을 받는 구조다. 공개 계약에서 아바타 이미지를 생성해 PNG/RGBA로 돌려주는 엔진은 확인하지 못했다. 따라서 Gleo 연동과 이미지 생성을 구분한다. [현행 계약](https://document.pleos.ai/docs/pleos-only/app-integration-guide/guide/core-concepts)

Nunti 적용안은 “이번 길의 눈티를 만들어 줘”로 생성 기능을 여는 것이다. App Schema 등록·승인과 실제 차량 연동은 필요하다. Action의 7초 제한 안에는 작업 접수 결과를 반환하고 이미지 완료는 앱에서 비동기로 처리한다. 이 흐름은 제안이며 아직 구현하지 않았다. [Schema 등록](https://document.pleos.ai/docs/pleos-only/app-integration-guide/guide/deliver-schema), [Callback 제한](https://document.pleos.ai/docs/pleos-only/app-integration-guide/guide/action_callback)

### 음성과 프로젝트 권한

TTS 문서는 ON_DEVICE에 서버 앱 등록·네트워크가 필요 없고 SERVER/HYBRID에는 My Project 자격 증명이 필요하다고 설명한다. 신규 프로젝트 접근 안내는 음성 SDK를 Not Available Yet으로 표시한다. API 문서의 존재, 로컬에서 이미 검증한 실행, 신규 프로젝트·공모전 참가자에게 허용된 서버 기능을 구분해야 한다. [TTS 모드](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/TextToSpeech/intro), [프로젝트 접근 안내](https://document.pleos.ai/en/docs/pleos-only/create-my-project)

Gleo가 응답하는 음성과 아바타마다 새 음색을 설계·보관하는 기능도 구분한다. 후자는 공개 계약에서 확인하지 못했다. [Gleo 조사](../research/2026-11-03-gelo.md)

## 지금 필요한 계정과 키

| 목적 | 준비할 정보 | 판정 |
|---|---|---|
| 현대 SDK 개발 | Pleos Playground 계정과 Nunti 프로젝트, 실제 SDK별 접근 상태 | 우선 확인. 프로젝트 ID와 필요한 권한을 관리 |
| Gleo로 Nunti 기능 호출 | `assets/schema.json`, Intent/Callback, 검토·승인 | 공개 안내는 일반 LLM API 키 발급 방식이 아님 |
| 경로 스크린샷으로 코어 시험 | 로컬 경로 이미지와 확인된 선/좌표 | v3 구현. 외부 내비 API 키 불필요 |
| 로컬 이미지 생성 | Python·Pillow의 프로젝트 렌더러 | v3는 새 RGBA를 직접 그림. 외부 생성 키 없이 사용 가능하며 AI 원화 생성은 아님 |
| 상용 이미지 생성 | v3 어댑터의 `OPENAI_API_KEY`와 모델·비용 설정 | 별도 명시 선택. 한 공급자 어댑터를 구현했고 실호출·품질은 미검증 |
| 기존 통합 실험을 그대로 실행 | `OPENAI_API_KEY`, `ELEVENLABS_API_KEY`, `GOOGLE_API_KEY` | 현재 코드의 요구사항이며 공모전 필수 요건이 아님 |

이전 v2는 이미지와 음성 세 clip을 함께 완료해야 READY이며 Google 평가도 필수다. v3는 별도 경계에서 이미지 결과와 기기 음성 미리 듣기를 분리해 로컬 키 없이 실행하고, 선택 AI 이미지에는 한 공급자의 키를 사용한다. v2 소장품·계약을 바꾸지 않았다. [v3 구현](../design/avatar-generator/README.md), [v2 구현 전 감사](../research/2026-11-03-product-focus-audit.md)

상용 API를 기본 후보로 둔 이유는 품질·실행 편의에 대한 선택이었다. 상용만 가능하거나 공모전에서 요구하기 때문이 아니다. 로컬 TTS에 대한 기존 사용자 평가를 로컬 이미지 생성의 한계로 일반화하지 않는다. 이미지 엔진은 동일한 내비 입력과 디자인 기준으로 비교한다. 현행 통합 실험 실행법은 [이전 API 설정 안내](../design/generative-mvp/API-SETUP.ko.md)에 보존한다.

아래는 사용자 담당 생성 기능의 상태다. 전체 제품의 주행 피드백 구현 상태나 운전습관 개선 효과를 이 목록으로 대신 판단하지 않는다.

**완료:** v3의 경로 사진·좌표 입력과 명시 확인, 새 로컬 768² RGBA, 실제 금빛 경로실 좌표에 이어지는 탄생 연출, 입력 특징과 외형 설명, 기기 음성 설정과 이미지 완료 분리, 원본·SHA·소장·재시작 복원, 선택 이미지 API 어댑터. Debug·release 공통 Android main 호스트를 연결했다. [통합 검증](../design/avatar-generator/test-report.md)

**미구현:** NaviHelper 실제 데이터 adapter, Gleo 연동·승인, v3의 새 음색 생성·기존 감정 피드백 모듈 실제 통합, 원격 배포 서버와 release 서명·제출 패키지.

**미검증:** 실제 공급자의 새 이미지·음색 품질·비용·지연, 공모전 프로젝트 권한·Gleo 승인, 실제 경로 전체 좌표, 귀여움·소장 의향·운전 습관 개선 효과.

현재 release에도 새 생성 호스트가 포함된다. 생성은 PC의 루프백 서버에 의존하고 APK는 아직 서명 전이다. release 빌드 통과를 공모전 제출 준비 완료로 보고하지 않는다.

사용자는 [직접 시험 안내](../design/avatar-generator/TESTING.ko.md)로 생성 기능을 바로 사용할 수 있다. 다음 연동은 생성 결과를 기존 감정·음성 피드백 모듈에서 사용하는 경계 검증, 가능한 현대 SDK의 실제 연결, 원격 서버·서명·제출용 release 검증이다. 외부 payload 담당 조율은 기존 보류를 유지한다. 기존 확정 소장품과 음성 바인딩은 보존한다.

외부 점수·최종 코멘트 담당 조율은 기존 보류를 유지한다. 녹화·녹음은 사용자의 명시적 요청 때만 한다. 공식 조사 이후 v3 앱·서버·일러스트를 구현했으며 실제 생성 API 호출·계정 등록·녹화·녹음은 하지 않았다.

전체 제품 목표·사용자 담당 기능·연결 모듈·담당 기능의 구현 상태는 [구조화된 범위](nunti-scope.json)로 분리했다. `python3 scripts/verify_product_scope.py`는 이 위계와 문서 시작점·정책·감사한 코드 해시를 검사한다. [검사 결과](../research/2026-11-03-scope-verification.json)는 앱 기능이나 실제 SDK 연결의 새 검증 결과가 아니다.
