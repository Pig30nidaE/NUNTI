# 여정마다 태어나는 수집형 캐릭터

2026-11-03 기준 **전체 제품 목표는 운전습관 개선을 도와주는 아바타 눈티**다. 이 브리프는 사용자 담당인 **목적지·내비게이션 경로 기반 아바타 생성 기능**을 다룬다. 생성한 눈티에 대한 애착이 주행 이벤트에 따른 감정·음성 피드백에 의미를 더하도록 한다. [제품 목표·담당 범위·공모전 기준](2026-hmg-app-challenge.md)을 우선한다.

현재 [생성기 v3](../design/avatar-generator/README.md)는 경로 사진·좌표 입력, 확인한 선에서 새 로컬 RGBA 생성, 탄생 모션, 외형 근거·기기 음성 설정·소장 복원을 연결했다. [직접 시험 안내](../design/avatar-generator/TESTING.ko.md)를 따른다. 로컬 조형 문법과 선택 AI 이미지 어댑터를 구분하며 실제 API 품질·새 음색·실제 내비 SDK는 검증하지 않았다. 아래의 “최신” 표기는 각 과거 검증 시점의 기록이다.

최신 생성 흐름은 [목적지·경로에서 동반자가 태어나는 시험본](../design/route-birth/test-report.md)을 따른다. 앱에서 목적지·특성·목적과 직접 그린 경로를 입력하면, 기존16윤곽 선택 없이 새72점 외형과 로컬 Sohee 음성을 생성한다. 경로 trace→몸체 morph→얼굴 등장, 런타임 음원 수신, 도착·보관·복원을 연결했다. 새5여정·15새WAV는 검증 표본이며 선택지나 생성 상한이 아니다. PC 모델/로컬 bridge가 필요하고 외부 API·계정은 사용하지 않는다. Anna 선호는 유지한다. 지도·내비 입력·폭넓은 자유 서술 해석·Android 추론·실차·사람의 품질 평가는 남았다. 아래8개 목록 방식은 이전 검증본이다.

2026-11-02 사용자 요구 변경. 이 문서는 기존 MVP의 고정 캐릭터·고정 전역 음성 방침보다 최신 제품 방향을 우선한다. 제품 구현 완료 문서나 공통 wire 계약 확정 문서는 아니다.

사용자가 원하는 것은 목적지, 주행 경로, 목적지의 특성, 방문 목적을 활용해 매번 이동할 때 새로운 2.5D 아바타를 생성하는 경험이다. 캐릭터 특성에 따라 TTS도 달라져야 한다. 품질의 핵심은 귀여움, 소장하고 싶은 개별성, 나만의 이동 기억과 연결되는 애착이다. 운전습관 개선 지원은 제품 목표이며, 캐릭터에 대한 애착과 피드백이 실제 개선으로 이어지는지는 검증할 가설이다. 디자인만으로 개선 효과를 보장하지 않는다.

사용자가 비교 시안에서 선택한 방향은 **C · 반투명 기념 오브젝트**다. 형태·내부 무늬·빛에 이동 기억이 담기는 살아 있는 작은 동반자를 기준으로 한다. 다른 아트 방향으로 재선택하지 않는다. [PM 통합 설계](../design/journey-characters/README.md)와 [C 수정 시안](../design/journey-characters/concepts/c-luminous-v2.png)이 후속 작업 기준이다. 수정 시안의 세부 형태와 품질까지 사용자 승인 또는 평가 완료로 해석하지 않는다.

후속 사용자 요청은 "TTS까지는 이어서 진행해주세요"다. TTS는 아래 초기 proposal-only 범위에서 이어서 실제 로컬 합성·음성 파일·Android 재생 연결을 구현한다. 범위와 소유권은 [TTS 구현 브리프](../design/journey-characters/tts-implementation-brief.md)를 따른다. 첫 음성 비교 뒤 사용자는 "전체적으로 더 작고 귀여운 느낌"을 선택했다. 이 피드백은 명시적인 시제품 캐스팅 수정이며, 기존 v1 표본과 binding을 보존하면서 별도 v2 후보를 만든다. 새 음성의 사람 평가를 완료했다고 해석하지 않는다. 후속 실제 구현·검증은 [PM TTS 결과](../design/journey-characters/tts-result.md)에 기록했다. 실제 v2 WAV·로컬 합성 도구·Debug Android 재생까지 완료했으며 제품의 자동 생성·새 2.5D renderer 연결은 남았다.

## 이번 설계 작업

- 같은 경로의 다른 여정은 새로운 캐릭터가 될 수 있다. 같은 생성 요청의 재시도·reroute·앱 재시작은 이미 정한 캐릭터를 보존한다.
- 세계관과 디자인 문법은 일관되게 유지하되 캐릭터의 실루엣·형태·재질·색·성격·이름·목소리는 여정에 맞춰 달라진다. 의상 교체만으로 새 캐릭터가 됐다고 판정하지 않는다.
- 출발 전 생성·선택, 이동 중 허용된 짧은 동행, 도착 후 추억·성장·컬렉션 보존으로 연결한다. 생성 대기나 실패가 출발과 로컬 안전 정책을 차단하지 않게 한다.
- 창작 모티브와 검증된 도로·운전 사실을 별도 데이터로 둔다. 사용자가 알려준 방문 목적·목적지 이미지는 창작 재료이며 실제 위험 이벤트나 GIS 검증 근거가 아니다. 미확인 운전 사실은 계속 UNKNOWN이다.
- 정밀 주소·GPS 원문을 생성 프롬프트에 자동 포함하지 않는다. 초기 설계·시안은 합성 여정과 의미 태그를 사용한다. 실제 feed 담당·payload 외부 조율은 사용자 요청에 따라 보류한다.
- 캐릭터별 음색·리듬·표현을 묶되 생성된 캐릭터 안에서는 음성 정체성을 유지한다. 실제 SDK/provider가 지원하는 음향 제어와 희망 메타데이터를 구분한다.
- 벌점·캐릭터 파괴·죄책감, 과속·장거리·위험 운전으로 얻는 희귀 보상은 사용하지 않는다. 운전 중 수집 조작을 요구하지 않고 검증된 긍정 행동의 피드백을 도착 후 다룬다. 점수·평가 의미는 기존 외부 담당 소유다.

## 담당별 요청과 작성 범위

PM은 루트에서 제품 요구·비교 시안·통합 설계·생성 레시피 프로토타입을 담당한다. 초기 설계 단계에서 각 담당은 자기 worktree의 읽기 조사와 설계 제안을 작성했다. 후속 TTS 구현은 별도 브리프에서 허용한 tts/voice와 Debug 진단 경계까지 진행했다. 이번 요청으로 기존 기능·wire v1·공통 Gradle·host를 바로 수정하지 않는다. 이전 복원 문서·검증 증거를 덮어쓰지 않는다.

| 담당 | 보고서 위치와 질문 |
| --- | --- |
| AVATAR | 자기 worktree `docs/design/journey-characters/avatar-proposal.md`. 기존 고정 identity 제약의 근거와 변경점, 2.5D 파츠/rig/표정/동작·화질·실루엣 평가, 새 여정과 재시도 ID·seed, 컬렉션 novelty/복원 경계를 제안 |
| TTS | 자기 worktree `docs/design/journey-characters/tts-proposal.md`. 실제 Pleos 지원·미지원 제어와 소스 근거, 캐릭터별 voice recipe·허용 음성 후보·실패 대체, 2~3 공급 방식과 실제 청취 검증 계획 제안. 외부 서비스 호출·비용 발생·자격증명 요청 없음 |
| SERVER | 자기 worktree `docs/design/journey-characters/server-proposal.md`. 여정별 생성 작업·멱등성·비동기 모델 작업·자산 provenance·컬렉션·동의/삭제·오프라인 경계와 wire v1 영향·계약 초안 제안. 서비스·DB·wire 변경 없음 |

보고는 기존 구현에서 확인한 사실, 새 제품 요구, 담당 제안을 구분한다. 변경할 수 없는 안전 정책과 단지 과거 제품 선택이었던 제약을 구분한다. 세션 간 index·공통 파일을 공유 수정하지 않는다. PM이 파일을 직접 읽고 취합한다.
