# Nunti visual problems

The current design works best when the journey can be read in one object. The Studio's matte color, rounded shapes, and restrained expressions give the local illustrations a consistent finish. The reveal turns the route into an understandable shape, and the same saved illustration carries into the native journey. Those are the parts worth keeping.

## P0 · Motion can outlive its permission

The native journey starts an 850 ms reaction when the companion is active and parked. The view returns early when the emotion value is unchanged. If the parked flag changes during that reaction and the emotion stays the same, the refresh can bypass animator cancellation. `onPause` removes the polling callback. The animator is explicitly canceled on view detach. This is a code finding. A live parked-to-restricted transition was outside the observed baseline. [Journey activity](../../android/app/src/main/kotlin/ai/nunti/app/journey/JourneyActivity.kt) · [Companion view](../../android/app/src/main/kotlin/ai/nunti/app/journey/JourneyCompanionView.kt) · [Pleos driving restrictions](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-developer-guide/driving-restriction-development-guide)

The parked Studio has a separate problem. It cancels the Canvas loop on host revocation and visibility loss, and returns to a still on re-entry. In an eligible window the 5.4 s reveal continues requesting frames after completion. This was observed in the installed Android WebView after the progress bar ended. The waiting trace also loops and ignores the reduced-motion preference. The preference is read once at startup and there is no visible Skip control. ## P1 · The illustration reads as a collection of different characters

The hooded sprout in the [named base sheet](../design/avatar-v6/assets/nunti-base-character.png) has large oval eyes, a forehead curl, a hood with a small sprout, a mint scarf, and a blue badge. The procedural v1 mascot is a cream bean with a single forehead seed. The v5 coast reference has a crest and curled tail. The v6 production Studio render can produce bears, foxes, penguins, and nine other body families. In the reviewed v6 contact sheets, ears, face proportions, poses, and props distinguish individual entries before any shared identity feature does. The fresh local result reads as a beret-wearing animal. Its features alone provide little connection to the hooded sprout. [Fresh result](baseline/2026-11-09-parked-result.png) · [v1 contact sheet](../../android/feature/avatar/demo/nunti-contact-sheet.png) · [v5 reference](../design/avatar-quality-v5/assets/style-clean-master.png) · [v6 art comparison](../design/avatar-v6/assets/art-prototypes/comparison.png)

This variety suited the earlier collectible-creature direction. The current design contract asks for one recognizable Nunti, even at thumbnail size. The route, destination, and purpose are clearest when they change a specific keepsake or gesture. The visual connection weakens when a route change also rerolls the body family and face. In the local-model path the structure reference can still show an animal family while reference image 2 contains the hooded sprout. An alpha contour establishes the image boundary. It does not establish facial consistency or whether a requested prop appears. ## P1 · Supporting text needs stronger contrast and scale

The Studio CSS sets helper text to 10 px and some labels to 7–9 px. The native report uses 11–13 sp for evidence, coverage, and status. Calculated contrast for the Studio's `#73817C` muted text is 3.66:1 on `#F4F3EE` and 4.04:1 on `#FFFEFB`. The same calculation gives 10.29:1 for primary `#253E3E` on `#F4F3EE`. The weak pairs affect readable route and state details, including the feedback that explains a disabled action. Pleos calls for 4.5:1 contrast in its UI design guide and recommends larger, consistently scaled type for in-car reading. The ratios here compare declared colors. Physical legibility, touch targets, focus order, and day/night behavior still require device checks. ## P2 · The reveal treats some data boundaries as visual details

The pre-trip UI places synthetic examples, imported NaviHelper data, API routing, screenshot upload, and coordinate files near one another. Provenance exists in the request and route receipt. Its presentation takes reading and scrolling. During animation, the contour can be visible before the face. The local-model artifact can have verified alpha geometry with an unverified face anchor. Keep that distinction when designing the transition. An effect that relies on a measured expression, exact facial rig, or road class has no reliable input on every existing artifact. ## Assessment boundary

I compared the fresh Pleos captures with older app captures, the named reference, art studies, fast-render and local-model contact sheets, and the saved motion key poses. The issues above are design or code findings. The audit did not measure driver glance time, run a new Figma comparison, or certify distraction behavior on a physical vehicle.
