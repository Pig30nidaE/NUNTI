# 눈티 Life V5 — 변신·표정·몸짓

2026-11-11. 정장에 파도가 나오던 매핑, 눈만 깜박이던 캐릭터, 눈 깜박임과 함께 WebView 전체가 하얗게 지워지던 문제를 수정했다. Debug·Release 빌드와 lintDebug를 통과했고 Pleos 에뮬레이터에 설치했다. Lint는 오류 0개, 기존 항목을 포함한 경고 56개다.

## 이번 변경

| 항목 | 적용 |
| --- | --- |
| 의상별 변신 | 정장은 금색 바느질 선·단추, 의사복은 민트색 맥박 선·둥근 입자, 축구복은 경기장 선·육각형 입자. 기본 눈티가 보이는 상태에서 같은 자리에서 변한다. 생성 의상에 바다 영상 에셋을 재사용하지 않는다. |
| 표정 6종 | 미소, 웃음, 호기심, 놀람, 걱정, 졸음. 얼굴 에셋의 눈·눈썹·입만 부드럽게 섞으며 기존 머리·후드·볼을 유지한다. 주행 이벤트의 걱정·안도·기쁨 연결도 유지한다. |
| 몸짓 8종 | 손 인사, 갸웃하기, 끄덕임, 웃음, 기지개, 놀람, 졸음, 축하. 대기 중 간헐적으로 행동하고 터치하면 순서대로 반응한다. 출발 전 화면과 여정 화면이 같은 동작 에셋을 쓴다. |
| 팔 분리 | 정장·의사복·축구복 원화의 팔을 분리하고, 팔 뒤에 가려졌던 몸통 원화를 추가했다. 소매와 옷자락을 함께 늘리는 방식은 제거했다. |
| 화면 깜박임 | 매 프레임 하드웨어 Canvas에서 눈 모양을 자르던 처리를 제거했다. 눈꺼풀과 얼굴 패치는 비트맵으로 준비하고 화면에는 일반 비트맵으로 그린다. |
| 주차 복귀 | D단·백그라운드에서 취소된 변신은 재생하지 않는다. 다시 주차·복귀하면 완성된 모습의 대기 동작과 터치만 재개한다. |

팔 부품은 현재 등록된 정장·의사복·축구복 **세 원화의 해시**에 맞춰 제작됐다. 새 API 이미지나 다른 원화에 같은 팔 마스크를 강제로 씌우지 않는다. 미등록 이미지는 원래 몸을 보존하면서 공통 얼굴·고개·호흡·상하 동작을 사용한다. 새로운 원화에 독립적인 팔 동작을 적용하려면 해당 이미지의 부품을 등록해야 한다.

## 디자인과 에셋

[Figma 연출 비교](https://www.figma.com/design/LHLHBra8ON3OdVW0qhBnbm?node-id=70-5)에서 A ‘의상 소재가 모이는 변신’과 B ‘무대가 펼쳐지는 변신’을 비교했다. 기존 원화를 중심에 두는 A를 적용했다. [표정 보드](https://www.figma.com/design/LHLHBra8ON3OdVW0qhBnbm?node-id=71-4)에는 실제 사용한 여섯 얼굴이 있다. 보드의 텍스트·레이아웃·도형은 Figma 네이티브 레이어이며 기존 눈티 변수를 사용한다. 얼굴·의상만 래스터 원화다.

에셋 위치: `prototypes/avatar_generator/nunti-life-v5/`

- `expressions.png`: 1536×1024 표정 원화. 런타임에서 배경과 후드를 제외한 얼굴 특징만 추출한다.
- `formal-underlay.png`, `medical-underlay.png`, `football-underlay.png`: 팔 뒤 몸통 원화.
- `manifest.json`: 표정 목록, 8개 동작의 키프레임·시간, 대기 스케줄, 소유자·프롬프트·출처·라이선스·대체 동작.
- `rigs.json`: 원화 해시, 좌우 팔 경계, 회전축, 소품을 고려한 회전량.
- `underlay-provenance.json`: 몸통 생성 원본과 프롬프트, 내보내기·라이선스 기록.

새 원화는 내장 image_gen으로 제작했다. 이번 수정으로 사용자의 OpenAI API 키에 추가 생성 요청을 보내지 않았다. 실제 확인 전후 wardrobe 호출 수는 모두 3회다. 사용자 품질 승인을 대신 표시하지 않았으며 `humanQualityApproved:false`를 유지한다. `MOCK_SKIN_MODE`와 기존 승인된 의상 API의 범위도 유지한다.

앱 전경의 `top` 두 표본에서 프로세스 CPU 표시값은 82.5–84%였다(`gates-final-2/cpu-current.txt`). 에뮬레이터 측정이며 실제 차량의 CPU 예산을 충족했다고 판정하지 않는다. 이전 `cpu.txt`는 프로세스 재시작 전 구간이 섞인 평균이므로 현재 사용량 근거로 사용하지 않는다.

화면 소실 검사는 고정 UI 영역의 색을 검사한 것으로 모든 종류의 렌더링 결함을 자동 검출하는 검사는 아니다. 대표 프레임과 세 의상은 별도로 눈으로 확인했다. 이전 실패 자료는 원인 비교용으로 남겼으며 최신 결과는 `final-2`와 `gates-final-2`다.

재확인 명령은 `scripts/verify_nunti_life_runtime.mjs`, `scripts/verify_nunti_life_gates.mjs`, `scripts/verify_nunti_video_flicker.swift`에 있다. 새 API 생성 없이 저장된 세 의상을 재사용한다. 차량 검사 출력 경로는 원상 복원 자료를 덮어쓰지 않도록 새 디렉터리를 지정한다.

## 이전 6개 구현사항의 연결

목적지·느낌별 의상 생성, 표정, 터치·대기 반응, 구간별 운전 리포트, UI, Pleos 점검의 기존 범위는 [Context V4 인계](CONTEXT_V4_DELIVERY.md)를 따른다. 이번 수정은 변신과 아바타를 교체하며 팀원의 점수 계산·GPS·리포트 저장 계약과 음성 기능을 변경하지 않는다.

장식 동작은 주차·전경·모션 허용 상태에서만 재생한다. `CarUxRestrictions`와 플랫폼 차단을 우회하지 않았다. 현재 에뮬레이터는 주행 중 앱 화면 전체를 차단한다. 기존 감사에 남아 있는 위치 차단 전용 팝업·차량별 심사 항목을 이번 아바타 검증만으로 완료 처리하지 않는다.
