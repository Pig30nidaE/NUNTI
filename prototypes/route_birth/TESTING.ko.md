# 경로에서 태어나는 Nunti 직접 시험하기

이 Mac에서 아래 실행 파일을 Finder에서 더블클릭하거나 터미널에서 실행한다. PC 생성기와 기존 Pleos 에뮬레이터를 함께 준비한다. 새 여정마다 APK를 다시 만들거나 설치할 필요는 없다.

```sh
open "/Users/pig30nidae/NUNTI/prototypes/route_birth/Start Route Nunti.command"
```

1. **어디로 떠나나요?**에 목적지를 입력한다. 그곳의 느낌과 여행 목적도 적는다.
2. 점이 있는 칸에서 마우스를 누른 채 경로를 이어 그린다. 이번 버전은 사용자가 그린 선을 사용하며 지도 길 찾기·GPS 입력은 연결하지 않았다.
3. **동반자 만나기**를 누른다. 입력한 경로가 그려지고, 몸체로 변형된 다음 얼굴과 빛이 나타난다. 외형의 색·비례·굴곡에 맞는 TTS 준비도 이어진다.
4. 음성 준비가 끝나면 조용한 시험 환경에서 **음성 시험 시작 → 인사 듣기**를 누른다. **응원 듣기**와 **중지**도 시험할 수 있다.
5. **도착했어요 → 도착 대사 → 동반자 보관**을 누른다. 왼쪽 보관 목록에서 다시 만날 수 있다.
6. 목적지나 경로를 바꾸고 다시 **동반자 만나기**를 누르면 새 여정과 새 캐릭터를 만든다. 같은 목적지·경로로 눌러도 별도 여행으로 생성한다. 앱을 닫았다 열면 선택·도착·보관과 확정된 외형·목소리를 유지하며 자동 발화는 하지 않는다.

처음 합성할 때는 로컬 모델 로드가 더 걸릴 수 있다. 합성 중에 이 Mac의 생성기를 종료하지 않는다. 연결이 끊어지면 앱의 **다시 연결**로 같은 요청을 재전송할 수 있다. 같은 요청의 재전송은 최초 외형·확정 음원을 유지한다. 이미 터미널 실패로 기록된 요청은 원인을 해결한 뒤 새 여행으로 생성한다.

음성은 이 Mac의 캐시된 Sohee 모델을 사용한다. 외형과 목적에 따라 말투를 지시하지만 새 화자를 복제하지 않으며 Anna의 API 재현도 아니다. 귀여움·소장 의향·목소리의 자연스러움과 외형의 어울림은 직접 판단할 항목이다.

차량 에뮬레이터에서는 P·속도0·알려진 화면 허가와 전경 상태가 필요하다. 다른 오디오가 있거나 앱이 백그라운드로 가면 음성을 제한한다. 다시 돌아오면 음성 시험을 다시 켠다. 일반 Android의 합성 시험은 실제 차량 허가와 분리한다. 실차 검증은 수행하지 않았다.

파일만 확인하거나 소스 수정 후 다시 빌드하려면 다음을 사용한다.

```sh
python3.12 scripts/run_route_birth.py --check
python3.12 scripts/run_route_birth.py --build
```
